## What changed from the inference-only tutorial

The previous notebook (`TASK-INFERENCE`, detection obligations) detected tables on a page rendered in code and reported `box_iou` against its drawn tables as sanity evidence. This notebook keeps the inference contract as Section 5 — on a real product photograph with reviewed reference boxes, so the domain gap is visible — and adds the adaptation contract around it: a real box-labelled corpus pinned per file, AP@0.5 / AP@0.75 / mAP and the operating points in the carried `metrics.py` with a fixed-box prior and the zero-shot checkpoint as reference points, new heads (frozen policy) and a bounded decoder unfreeze (unfrozen policy) under the DETR set loss implemented in the carried module, selected on validation, before/after detections, and an artifact that reloads. `evaluate` is the labelled corpus-level stage (`measured` / `measured-small-sample`).

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import. Section 2 embeds the repository's 3 modules verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative and remove internal relative package imports) — the 121-row pinned photo table travels inside the carried `samples.py` — Section 3 carries the 4-file snapshot manifest inline and asserts it against the module's constants before fetching, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries a fresh clone lacks (the git-ignored `model.safetensors`), at the pinned revision; `verify_snapshot` re-hashes every entry; `TableTransformerDetectionPipeline.from_pretrained(weights_dir=WEIGHTS_DIR)` loads with `local_files_only=True`, `trust_remote_code=False` and `use_pretrained_backbone=False`; no cell outside the carried modules calls `huggingface_hub`, `transformers`, `safetensors`, `urllib`, `scipy`, the model, the processor or the decoder outputs directly.
- **Data (DAT1–DAT9, ST6):** the default sample is 121 pinned objects — `<barcode path>/<image id>.jpg` from `static.openfoodfacts.org`, 129,318,620 bytes in total, one SHA-256 each — CC BY-SA 3.0 images with ODbL boxes from the Open Food Facts nutrition-table detection dataset v1.1, each refused on any mismatch before it is decoded, then downscaled to 1,280 px, and drawn by a seeded shuffle of whole products into 72 / 24 / 25 photographs (`check_split_disjoint` asserts no shared photograph by decoded-pixel digest and no shared product; `split_summary` reports photographs, boxes and products per split). The template adds a second *External access* bullet naming the host, the byte count and the licences.
- **Stages (§4.1):** `fetch_corpus` + `read_corpus` + `build_sample_dataset` / `load_byod_dataset` + `split_dataset` (sample acquisition) → `validate_dataset` + `check_split_disjoint` + `split_summary` + refusal probes (validation, with three digests) → `validate_inputs` + `pipe.detect` with sanity checks + `evaluation_report` against the photograph's reference boxes (inference contract, `sample-sanity`) → `prior_baseline` + `pipe.evaluate_zero_shot` + `pipe.adapt(trainable_layers=0)` + `pipe.evaluate` (prior, zero-shot row and frozen policy) → `pipe.adapt(trainable_layers=TRAINABLE_LAYERS)` (unfrozen policy, selected on validation) → `pipe.evaluate` on validation and test with the comparison (evaluation) → `pipe.detect_adapted` before (a fresh pipeline with heads trained the same way) and after, with `detect` beside them (inference) → `pipe.save_artifact` → `TableTransformerDetectionPipeline.from_artifact` with the parity assertion (export and reload).
- **Detection obligations and score semantics (UNC1–UNC4):** every box is xyxy in input pixels; AP is computed over all queries and is threshold-free, the operating points at 0.9 (the base `DETECTION_THRESHOLD`) and 0.5 are reported beside it and the notebook states that the adapted class needs its own operating point; the new head's softmax is a ranking signal under a 0.1 no-object weight, not a calibrated confidence; no acceptance threshold ships.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the fixed-box prior, the zero-shot checkpoint and the frozen policy are scored on the same 25 test photographs as the selected policy, per-image rows are printed beside every mean, the selection rule is stated (lowest validation set loss, the heads competing as epoch 0) and the notebook asserts only that the heads and the selected model beat the prior — a gain over the heads is the question, not an assertion; every metric is labelled as one seeded split of one small corpus with no dispersion estimate (one box ≈ four points of recall).
- **Split integrity (SPL1–SPL8):** the split is seeded, drawn by whole products and photograph-disjoint by decoded-pixel digest; validation selects the epoch and policy and the test split is used for nothing but the final evaluation, the before/after render and the reload-parity check; the notebook states that real data must be split by product, session or device.
- **Ceilings (VAL6):** `MIN_IMAGE_SIDE` (16), `MAX_IMAGE_SIDE` (4,096), `MAX_DETECTIONS` (15), `NUM_QUERIES` (15), `D_MODEL` (256), `DECODER_LAYERS` (6), the record bounds (8..2,000), the box bounds (1..15 per image, ≥ 4 px sides) and the id pattern are stated in the Prerequisites and printed before the model runs; four dataset refusals and one threshold refusal are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, user images flow through the same validation, seeded group-disjoint split, prior, zero-shot scoring, both policies, evaluation, rendering, export and reload cells; images inside the uploaded zip are decoded from the archive, never extracted. The expected schema and the privacy guidance — product photographs can show hands, homes and receipts — are stated in the Prerequisites and in Section 4, and the training boxes table is written to `outputs/table_transformer_detection_train.csv` in that shape.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
